# de-project-bibip
# Система управления данными автосалона «Бибип»

### Описание проекта
Проектирование и разработка кастомной легковесной СУБД для автоматизации операционных процессов, складского учета и анализа продаж автосалона. Проект реализует логику долгосрочного хранения данных в плоских файлах и их обработку с помощью встроенных средств Python (без использования сторонних реляционных СУБД) с применением механизмов индексации для оптимизации поиска.

### Технологический стек
* **Язык программирования:** Python 3.x
* **Валидация и сериализация:** Pydantic (модули `model_dump_json`, `model_validate_json`)
* **Управление путями и файловой системой:** Pathlib, File I/O (встроенные конструкции контекстных менеджеров `with open`)

### Архитектура СУБД и механизмы оптимизации
Для обеспечения высокой скорости выборки данных и минимизации нагрузки на дисковую подсистему в проекте реализована **кастомная система индексных файлов** (`models_index.txt`, `cars_index.txt`, `sales_index.txt`). 
* При инициализации или обновлении объектов система записывает в индексные файлы связку `Ключ (ID/VIN) | Сдвиг (Номер строки в основном файле)`.
* Это позволяет осуществлять поиск и точечное обновление данных в основных файлах за константное время O(1), избегая полного сканирования (Full Scan) тяжелых текстовых массивов.

### Техническая карта методов класса `CarService`

Интерфейс системы разграничен под ролевую модель доступа (клиенты, менеджеры, управляющие) и включает в себя следующие ключевые методы:

* **add_model(model: Model) -> Model** — Инициализация и сохранение новой модели автомобиля. Реализует сериализацию объекта через Pydantic в JSON-строку, запись в основной файл `models.txt` и параллельную фиксацию метаданных в `models_index.txt`.
* **add_car(car: Car) -> Car** — Постановка автомобиля на учет (в наличие или под заказ). Генерирует JSON-запись физической единицы авто и обновляет индекс по ключу `VIN`.
* **sell_car(sale: Sale) -> Car** — Обработка финансовой транзакции продажи. Фиксирует запись о сделке в `sales.txt`, находит связанный автомобиль по индексу и атомарно меняет его статус на `sold`.
* **get_cars(status: CarStatus) -> list[Car]** — Метод фильтрации и выборки данных. Осуществляет поиск и возвращает массив автомобилей на основе их текущего коммерческого статуса (`in_stock`, `expected`, `sold`).
* **get_car_info(vin: str) -> CarFullInfo | None** — Метод сборки агрегированной информации об автомобиле. Реализует паттерн, аналогичный операции `LEFT JOIN` в реляционных СУБД: по VIN находит сдвиг строки автомобиля, извлекает его данные, сопоставляет ID модели с файлом `models.txt` для получения технических характеристик, а в случае статуса `sold` — обогащает объект финансовыми данными из архива транзакций `sales.txt`.
* **update_vin(vin: str, new_vin: str) -> Car** — Метод каскадного обновления ключевого поля (VIN-номера). Реализует атомарное изменение данных: точечно перезаписывает JSON-строку автомобиля, обновляет соответствующий индекс в файле `cars_index.txt` и производит обязательную сортировку индекса для сохранения консистентности данных.
* **revert_sale(sales_number: str) -> Car** — Метод отката финансовой транзакции (удаления продажи). Демонстрирует умение работать с целостностью данных: удаляет запись о продаже из `sales.txt`, находит связанный автомобиль по VIN через файл индекса и восстанавливает его статус до `available`.
* **top_models_by_sales() -> list[ModelSaleStats]** — Аналитический метод (аналог SQL-запроса с операторами `GROUP BY` и `ORDER BY`). Собирает историю продаж, агрегирует количество проданных машин с помощью словаря-счетчика, сортирует данные по убыванию популярности моделей и возвращает топ-3 самых продаваемых автомобилей с детальной информацией по каждой модели.


## Настройка среды разработки

Рекомендуем использовать редактор [Visual Studio Code](https://code.visualstudio.com/).

vscode при запуске импортируем переменные среды из файла `.env` и запускаем отладку.

Чтобы в редакторе работала подсветка импортов, а при запуске все зависимости корректно подтягивались, создайте файл `.env` в корне проекта и добавьте в него следующие строки:
```bash
PYTHONPATH="$PYTHONPATH:full_path_to_src_folder_in_project"
```
где full_path_to_src_folder_in_project - полный путь до каталога src.

Этой командой вы добавляете каталог src в переменную окружения PYTHONPATH, чтобы python мог найти все модули в проекте.

После того, как вы создали файл `.env`, перезапустите vscode. Все импорты должны подсвечиваться корректно.


## Запуск тестов в консоли

Если вы хотите запустить тесты в консоли, вам так же нужно добавить переменную окружения PYTHONPATH. Для этого выполните следующие команды:
```bash
export PYTHONPATH=$PYTHONPATH:full_path_to_src_folder_in_project
```
где full_path_to_src_folder_in_project - полный путь до каталога src.

После этого вы можете запустить тесты:
```bash
cd de-project-bibip # переходим в каталог проекта
pytest tests # запускаем тесты
```

## Запуск проекта в докере

Если вы не сталкивались с докером, просто проигнорируйте файлы `Dockerfile` и `docker-compose.yml`. Вы еще познакомитесь с докером, дальше на курсе.

Если вы предпочитаете разрабатывать в докере, то вам нужно выполнить следующие команды:
```bash
cd de-project-bibip
docker compose up -d --build
```

После завершения работы остановите контейнер:
```bash
docker compose down -v
```
